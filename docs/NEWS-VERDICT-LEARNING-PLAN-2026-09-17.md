# 新聞判讀層的整合與「精準成長」執行計畫（2026-09-17）

狀態：**評估與設計文件，尚未動工**。使用者要求先做成可行的執行與說明文件，再決定最佳化順序。
本文件所有數字都來自 2026-09-17 線上文件（`newsVerdict`／`newsVerdictReview/summary`／`picksScoreboard`），不是設計值。

---

## 0. 一句話結論

新聞判讀現在是「把新聞分類」，不是「預測市場反應」；對答案顯示它**反向**。要讓它精準成長，
不是再改 prompt，而是把它拆成三層——**LLM 抽事實 → 統計校準 → 進模型當特徵**——並且每一層各自對答案。
判讀能力的「成長」發生在校準層與經驗庫，LLM 本身不必每天變。

---

## 1. 現況（證據）

### 1.1 管線
- 來源：鉅亨（分類／搜尋）、經濟日報 RSS、Google News RSS、DuckDuckGo 補抓內文；論壇一律禁用。
- 判別：本機 Ollama `gemma4`，每檔讀近 2 日內文，三段式（多角色初判 → 四挑戰 → 定案），輸出
  `label／confidence／strength／reason／keyQuote／impactPath／priced／challenge…`（結構已相當完整）。
- 排程：盤後趟、晨間 07:00 趟、盤中趟；宇宙＝各榜候選約 180 檔。
- 對答案：`computeNewsVerdictReview`，標的＝適用交易日**開盤→收盤**，利多組減中性組＝`newsLift`；
  門檻 n≥200／≥200／≥15 日才算 conclusive。
- 消費端：評分器保留 ±20 調分的位置，但目前**未據 newsLift 加權**（程式註解明說要等對答案）。

### 1.2 對答案（14 個交易日，2026-09-17 讀取）

| 判別 | n | 開→收均值 | 勝率 |
|---|---|---|---|
| 利多 | 1,172 | −0.293% | 43.9% |
| 中性 | 906 | +0.062% | 47.1% |
| 利空 | 63 | −0.284% | 42.9% |

newsLift＝**−0.355pp**。今天的 180 檔分布：利多 72、中性 72、資訊不足 33、利空 3。

### 1.3 診斷（為什麼會反向）
1. **選擇偏誤**：能被寫成利多新聞的公司，多半股價已先漲；判別在「開盤前」做，開盤已反映，開→收回吐。
   prompt 有 `priced`（是否已反映）欄，但對答案沒按它分組，評分也沒用它。
2. **問錯問題**：prompt 要模型判「是否構成實質利多」（事實層），對答案卻在量「市場反應」（價格層）。
   兩者中間缺一層「這類事實在這種狀態下市場通常怎麼反應」——那是統計，不是語言模型該猜的。
3. **標籤失衡**：利空 5%。規則 3b 已要求「利空是正常結論」，但模型仍傾向利多／中性；沒有回饋機制矯正。
4. **單一評量口徑**：只量開→收。新聞的效應可能在**跳空**（昨收→今開）就出完，或延到 3～5 日。單看開→收，
   一個「開高走低」的正確利多會被記成錯。
5. **沒有學習迴路**：14 天累積的 2,141 筆「判別＋結果」躺在文件裡，沒有回到 prompt、沒有回到權重。
6. **層級缺失**：判別是逐檔的；「產業新聞 → 族群 → 個股」只靠 prompt 第 7～9 條讓模型自己推，沒有產業層的獨立判別與對答案。

## 2. 目標架構：三層＋回饋

```
資料層   MOPS 重大訊息(新增·第一手) ＋ 媒體(現有) ＋ 產業現貨報價(新增) ＋ 交易所名單(注意/處置/節目推介)
   │  去重(同一篇文章只判一次·以 canonical URL)
   ▼
L1 抽取層（LLM，固定 prompt，只做「發生了什麼」）
   輸出結構化事件：type(訂單/財測/法說/擴產/法律/處分/減資/併購/產業報價/宏觀…)、
   direction(對本公司)、magnitude(金額或幅度·可查證)、certainty(已確認/預期/傳聞)、
   novelty(首次/重複)、priced(股價是否已反映：近5日漲幅、量)、chain(連動路徑·標推論)、
   quote(原文句)、source、publishedAt
   ── 不輸出「市場會漲多少」。
   ▼
L2 校準層（統計，每日重算，會成長）
   key = (type, direction, certainty, priced 分層, 產業, 市況 regime)
   value = 歷史上同類事件的 跳空／開→收／5日超額 的分布（均值、勝率、n、信賴區間）
   → 每則事件得到「校準後預期反應」與「可信度」；n 不足時向 0 收縮(shrinkage)，不捏造。
   ▼
L3 整合層（進模型當特徵，與籌碼/技術/市況同層）
   個股：newsScore = Σ 校準後預期反應 × 新鮮度衰減；只有 |分| 過門檻且 n 足夠才生效。
   產業：sectorNews = 產業層事件的校準值，加到 產業風向/族群輪動；再以連動係數分配到成分股（推論，權重打折）。
   宏觀：regime 覆寫（戰爭/關稅/利率 事件日 → 全體降倉或只留特定族群）。
   ▼
回饋（每日對答案 → 每週升降 → 每月重估）
   L2 表每日用新結果更新；L1 的系統性錯誤由「錯誤樣本佇列」整理成 prompt 規則（人審後加入）；
   L3 的權重每月用 bt-core 四窗檢定，通過才上線，帶版本章。
```

「互相牽動」在這個架構裡的處理原則：**同一則事實只判一次，方向分別套到個股／產業／宏觀三個層級，
各層各自對答案、各自校準**；層與層之間只傳「校準後的數值＋可信度」，不傳文字結論，
所以產業層錯不會直接污染個股層，宏觀 regime 則有權覆寫兩者（優先序：宏觀 > 產業 > 個股）。

## 3. 「精準成長」的具體機制（由便宜到貴）

| # | 機制 | 做什麼 | 為什麼會成長 | 成本 |
|---|---|---|---|---|
| M1 | **多口徑對答案** | 每則判別記 昨收→今開、開→收、昨收→今收、5日超額（對宇宙）；按 label×confidence×strength×priced×type 分組 | 現在只有一個口徑，看不出錯在哪一層；分組後才知道「利多但已反映」和「利多且未反映」是兩群 | 低（daemon 一支函式） |
| M2 | **校準表（L2）** | 由 M1 的分組結果算「校準後預期反應」，寫 `newsCalibration/latest`；評分只用校準值 | 每天多一天資料，表自動變準；LLM 不變 | 低 |
| M3 | **已反映偵測** | L1 的 `priced` 改成規則＋數據：近 5 日漲幅、量比、是否已漲停、新聞首發時間 vs 價格反應時間 | 直接針對 1.3-1 的反向來源 | 低 |
| M4 | **利空再平衡** | 針對 MOPS 負面公告類型（處分、減資、財測下修、法律）強制走利空判定分支；對答案分利空類型 | 修 5% 失衡 | 低 |
| M5 | **經驗庫（few-shot 檢索）** | 把「判別＋結果」中最典型的對與錯各存 200 則，L1 判別時依事件類型檢索 3～5 則塞進 prompt | 模型看到「上次這樣判結果如何」，不必微調就能修正 | 中（需向量檢索，本站已有 wm-browser-ml 技能參考） |
| M6 | **錯誤樣本佇列＋規則審核** | 每週列出「高信心卻反向」的判別，人工看後把系統性錯誤寫成 prompt 規則（現有 3／3b／3c 就是這樣來的，改成制度） | 把個案修正變成流程 | 低 |
| M7 | **事件類型 × 市況 的 L3 模型** | 以 L1 結構化特徵＋籌碼技術特徵訓練小模型（邏輯迴歸／GBM）預測 5 日超額；LLM 只當特徵抽取器 | 把「預測」交給會校準的東西 | 高（需 M1 累積 ≥60 日） |
| M8 | **產業層判別** | 產業新聞（報價、政策、龍頭財報）獨立判一次，寫 `sectorNews`，對答案用族群等權報酬 | 現在靠模型逐檔推連動，重複算又不可驗證 | 中 |
| M9 | **本機模型微調（LoRA）** | 等 M1 累積數千筆帶結果的樣本再考慮 | 只有樣本夠才值得，否則過擬合 | 高、暫緩 |

**不做的事**（違反本站硬規定或已證偽）：標題關鍵字調分；只讀標題；論壇來源；每日改權重追市況；
把 LLM 的「強度」直接當分數。

## 4. 與現有選股系統的整合點

| 消費端 | 現況 | 整合後 |
|---|---|---|
| 隔日沖評分（±20 調分位） | 保留但未啟用 | 改為 L2 校準值，門檻：n≥100、95% CI 不跨 0、priced≠已反映；否則 0 |
| 軋空候選 `verdict` 標籤 | 顯示 label／confidence | 改顯示校準後預期反應與 n（例：「利多·同類 n=84·5日+0.8%」） |
| 波段起漲／追強 | 無新聞 | 加 sectorNews 與個股 newsScore 當排序次鍵，不當 gate（等對答案） |
| 漲停預測 | 無新聞 | 產業層事件當族群加權；個股層只在 certainty=已確認 才計 |
| 產業風向／族群輪動 | 價量 | 加 sectorNews（M8） |
| 早盤機會推播 | 昨日策略榜 | 加「新聞事件日」標記與校準值，避免推已反映的 |
| 問 AI 技能注入 | 讀 latest verdict | 注入校準值與同類歷史，而不是文字結論 |

規則：**任何消費端只能讀 L2／L3 的數值，不能直接讀 L1 的 label 做決策**。這是「同名同口徑」與
「不捏造」在新聞層的實作。

## 5. 執行順序與驗收（分四段，每段可獨立停）

### 第一段（1～2 個工作天）：先把量尺做對
- M1 多口徑對答案（含 priced 分層、事件類型分層）→ 產出 `newsVerdictReview/breakdown`。
- 判別文件加 `eventType／certainty／novelty`（L1 輸出欄位擴充，prompt 只加抽取欄，不改判定規則）。
- MOPS 重大訊息接入（僅抓取與去重，先不判）。
- **驗收**：能回答「利多且未反映」「利多但已反映」兩群的 5 日超額各是多少；利空樣本開始累積。

### 第二段（累積 10 個交易日後，1 天）：校準表上線（影子模式）
- M2 校準表＋M3 已反映偵測＋M4 利空再平衡。
- 評分器讀校準值但**只記錄不生效**（影子欄位），與現行並列對答案 10 日。
- **驗收**：影子模式的 newsLift 相對現行至少轉正；未轉正就不啟用。

### 第三段（1～2 天）：成長迴路
- M5 經驗庫、M6 錯誤佇列與週審流程、M8 產業層判別。
- **驗收**：每週報表列出「校準表變化」「錯誤佇列處理」「產業層對答案」。

### 第四段（第一段累積 ≥60 交易日後）
- M7 小模型；只有通過四窗檢定才取代校準表；M9 視樣本量再議。

每段上線都掛版本章（沿用 `calib` 機制），記分板新舊分開算。

## 6. 資源與風險

- **算力**：現在每檔判別約 90 秒、180 檔約 4.5 小時，已是本機 Ollama 上限（實驗 ⑥ 證明並行無效）。
  對策：同一篇文章只判一次（去重後估可省 30～50%）、產業層文章判一次後傳播、個股層只判候選。
- **時點正確**：MOPS 公告帶精確時間；媒體稿要以「首次出現時間」為準，對答案不得用發布後才成交的價格。
- **不可驗證的連動**：推論性連動一律信心上限「低」、進 L2 時單獨分組，不與已確認事件混算。
- **會失敗的樣子**：校準表 n 永遠不足（候選宇宙太小）→ 第一段就要把宇宙從候選擴到「有新聞的所有股」抽取（不判、只抽），
  判定只給候選；否則 L2 永遠稀疏。
- **最壞情況**：三段做完 newsLift 仍不顯著 → 結論是「這批來源的新聞對隔日／5 日沒有可交易的訊息」，
  新聞層降為風險提示（利空、法律、處分）不做多方訊號。這也是有價值的答案。

## 7. 待使用者決定
1. 是否先做第一段（量尺）；它不改任何選股行為，只多存欄位與對答案。
2. MOPS 重大訊息是否要接（免費、官方、第一手，我建議接）。
3. 產業現貨報價來源（記憶體／面板／運價）是否要納入第一段抓取（部分來源需付費，先接免費的）。
