## 0. 結論先講（8 點）

1. 這兩張卡 80% 的數字，今天就能用**本機現成檔案**算出來：`second-brain/daily-heatmap/{日}.json.gz`（近 60 日、已含 market／industries／index 權值股貢獻／breadth／board／watch／stocks）＋ `official/www.twse.com.tw/twse_mi_index`（1,023 日，含成交統計、官方漲跌家數、類股指數）＋ `backup/chipArchive`（1,024 日：收盤／量／外資投信／資券／借券／當沖）＋ `backup/chipDaily`（175 日，含自營商）。
2. **三大法人金額、期貨未平倉、融資融券金額的「前一日」對照，官方鏡像目前只有 10-02 一天**（BFI82U、taifex_*、MI_MARGN／TWT93U 尚未落地）。能自算的：法人金額＝`T86 股數 × MI_INDEX 收盤`（10-02 實測與官方 BFI82U 差：外資 +6.7 億、投信 +0.3 億、自營 +3.5 億）。**期貨與選擇權「較前日」目前不可寫**，只能寫當日值。
3. 站上有**兩個資料缺陷會直接害 AI 寫錯**（見 §8）：`taifexPositions.foreignTxfNetOI = -3,862` 與官方 CSV 外資臺股期貨未平倉淨額 **-80,304 口** 不符；漲跌家數同一天在站上有 5 種口徑。資料包必須走官方鏡像、並統一口徑。
4. **「與上一交易日有什麼不同」建議 14 個指標**（§3），每個都由程式預先算好 delta 與「方向詞」，AI 只寫句子、不做算術。
5. 「交易動能」指標裡**有實測依據的很少**（§4）：族群熱度隔日超額 IC 0.08–0.095（40% 來自連板）、隔夜溢價、當沖比／量比／法人同向（研究層、影子模式中）。權值股貢獻占比、廣度（漲家數<跌家數）、國際盤閘門、五秒委託失衡、期貨 P/C **都沒有或已證偽的預測力**——只能描述，不能暗示方向。
6. 個股 5–10 檔：**AI 不選股，只寫理由**。程式產 ~25 檔候選短名單（§5：配額＋機械排序＋排除），AI 只能從中挑並引用證據欄位。實作示範 10-02 得 8 檔（台特化、上詮、欣興、新唐、台積電〔拖累〕、南亞科、力積電、南電）。
7. 防亂寫的核心做法：**AI 輸出「佔位符模板」，數字由渲染層從資料包填入**（零數字幻覺），再加方向詞、因果句、價格目標、口徑標籤、日期詞的機械查核（§6）。
8. 與其他分析師的接口：我提供「今日資金主場＋異動個股代號清單＋指數／量能狀態」；我需要「個股事件／公告的可引用事件 ID（產業與本土消息）」與「**D−1 夜盤**的全球背景（全球與總經）」。時間對齊規則見 §7（D 日美股收盤在台北 D+1 凌晨，屬明日預期卡）。

順序理由（**先驗**）：先結論（P0）→ 再對照（P1，使用者最想知道的「差異」）→ 再解釋差異的來源（P2、P3）→ 再問動能強弱（P4）→ 再看誰在買賣（P5）→ 最後落到個股（P6）。P2 放在 P3 前是因為「指數漲跌被誰決定」是解讀輪動的前提（10-01 台積電單檔貢獻 +238.3 點＝當日 +413.36 點的 57.6%；10-02 台積電 -79.4 點而指數仍 +122.25 點，**這個反差就是 10-02 相對 10-01 最大的不同**）。

## 5. 個股推薦（5–10 檔）——「今日盤後」「昨日股市」兩卡的選股設計

### 5.1 設計原則

1. **AI 不選股，只寫理由**：程式產出 20–30 檔候選短名單＋證據欄位；AI 只能從短名單選、不得新增代號（機械查核 §6-R11）。
2. 名稱用「**重點觀察個股（描述性）**」，不稱「推薦買進」；不附買進價、目標價、停損價、報酬預期；全文附「非投資建議、未扣成本、研究期不計分」。
3. 排序鍵不用「漲幅最大」（會選到買不到的漲停）；以**流動性（成交值）與證據完整度**為先。
4. 每個類別有**配額上限**，類別無合格者就**空缺不遞補**（寧缺勿濫）；總數 5–10；合格不足 5 檔時，成交值門檻由 10 億放寬一次到 5 億，仍不足就發布 n<5 並註明，不再放寬。
5. 不使用任何站上評分欄位（`/api/rating` 的 score、各 picks 榜單）。理由：①熱力檔規定不進／不出模型；②含處置扣分的 score 只拿來排序（memory：處置／注意扣分≠走勢弱）；③避免與「選股」頁推薦重複並互相矛盾。

### 5.5 如何避免變成買賣訊號或價格目標

- 渲染層強制欄位白名單：代號、名稱、類別、報酬%、成交值、法人金額、貢獻點、共振標籤、**證據一句話**；**沒有價格欄**（收盤價都不放，避免被讀成價位）。
- 禁詞（§6-R2）：買進、賣出、加碼、進場、停損、目標價、上看、支撐、壓力、續強、看好…
- 每檔固定附一句反向資訊（先驗）：例「成交值前 5 大、外資當日賣超 147.8 億」，避免單向包裝。
- 比對一律未扣成本，並註明：成本依當沖（證交稅 0.15%）／隔日沖與波段（0.3%）另列，不當門檻。

### 6.2 AI 容易亂寫的點與機械查核（先驗；全部可程式化）

| # | 風險（實例） | 機械查核規則 |
|---|---|---|
| R1 數字幻覺／算錯（把 +122.25 寫成 +112.25；自己算「占比」） | **佔位符模式**：AI 輸出 `{{idx.pct}}`，渲染層填值；若 AI 輸出裸數字（regex 抽 `\d`）必須 ∈ 資料包數值白名單（容忍四捨五入與單位換算），否則整句丟回重寫；**禁止 AI 做算術**（差、比、占比全預算） |
| R2 預測／方向詞（「續強」「有望」「看好」「預期明日」） | 禁詞表：預計、預期、將、可望、有望、看好、看多、看空、續強、突破、支撐、壓力、目標、停損、買進、賣出、加碼、進場、上看、下探、勢必、料；「明日／隔日」只能出現在「明日預期卡」。命中即退稿 |
| R3 價格目標與價位（舊 `marketReports.topPicks` 的 buy/target/stopLoss） | 個股句子禁止出現「元」＋價位；欄位白名單無價格；regex 擋 `\d+(\.\d+)?\s*元`（除總成交值、類股指數點數外） |
| R4 口徑混用（漲家數 5 種；成交值 4 種；法人張 vs 億） | 每個數字的 id 帶口徑標籤；句子若同時引用兩個不同口徑的「上漲家數」或「成交值」→ 退稿；法人金額與張數不可出現在同一比較句；規定家數預設用「官方上市」與「官方兩市合計」，並於句首標明 |
| R5 日期錯位（「昨天」＝日曆昨日、週末當資料日） | 所有日期 token 必須 ∈ {D, D−1} 的 ISO／民國寫法或「資料日／前一交易日」；禁「昨日／今日」以外日曆詞（週五、上週）；`meta.prevDate` 由交易日清單產出 |
| R6 把「描述」寫成「因果」（「因台積電下跌所以…」「權值股拉抬導致」） | 禁因果連接詞表：因為、由於、導致、帶動、拖累了（可保留「貢獻 X 點」）、使得、所以、造成；改為並列句「同時」。事件原因只能引用其他分析師提供的事件 ID |
| R7 權值股貢獻解讀為多空（SKILL §5 已否證） | 句式白名單：只能出現「貢獻 X 點／占當日漲跌 Y%」，禁止後接任何明日推論 |
| R8 引用不存在或缺失的資料（期貨「較前日」、BFI82U 前日） | 若句中引用的 id ∈ `missing`→ 退稿；`missing` 欄位只能被寫成「來源未提供」固定句 |
| R9 方向詞與 delta 符號矛盾（「量增」但量比<1；「收斂」但差擴大） | 詞表→欄位→符號對照：增／升／擴大 ⇒ delta>0，減／降／收斂 ⇒ delta<0；不符退稿 |
| R10 熱度解讀漏 caveat（族群熱度必附「約四成來自連板」） | 句子含 `industries.heat` 引用時，必須同段含 evidence id `heat.caveat40` |
| R11 個股越界：加入短名單外代號、檔數≠5–10、代號與名稱不符、含處置／可能處置／漲停 | 後置查核：①code ∈ `poolShortlist`；②5≤n≤10；③code→name 對照資料包；④`exclusionChecks` 全為通過；⑤每檔證據欄 ≥3 項且皆引用存在的 id |
| R12 買賣語氣、績效宣稱（「推薦成績」「勝率」） | 禁詞「推薦」（改「重點觀察」）、「勝率」「報酬率將」；昨日對帳句必須含「n、單日、不構成績效」固定尾句 |
| R13 「不計分」違規：寫出「分數／評分／訊號／排名第 N」 | 禁詞（除固定免責句）；熱度只能叫「熱度名次」且需附 §4 標籤 |
| R14 免責缺失 | 每卡末尾固定句：「描述資料日收盤事實，研究期不計分、不進任何模型；比對未扣成本；非投資建議」，由渲染層附加，AI 不可刪 |
| R15 資料不完整仍下結論（`otcPending`、殘差「紅」、歷史重建日） | 閘門：`gates.heatmapCanonical!==true` → 整卡拒寫；`residualGrade==='紅'` → 停用 P2；`otcPending` → 停用兩市合計句；`rebuilt` → 每句加「重建資料」註 |
| R16 與其他分析師／既有模板矛盾（現有 `scripts/lib/daily-heatmap/narrative.mjs` 已有零 LLM 的 overview／index／sectors／stocks 段） | 總編輯階段做「事實一致性比對」：同一 id 在各卡引用值必須相同；與 narrative 模板的數字不一致→標紅 |

**驗收建議（先驗）**：以 §3 的 14 指標做 golden test——給定 10-01／10-02 資料包，渲染結果的每個數字必須逐一等於本文表中值；退稿重寫最多 2 次，仍失敗則降級為純模板輸出（不經 AI）。
