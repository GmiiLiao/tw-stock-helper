## 本輪新發現（4 項）

### 1. 🔴 `uid` 仍來自 request body — 權限繞過還沒補完

`ai-analysis` 的 POST trigger 上一版改成「只信 Firestore 讀出的 `userData`」，
但 `userData` 是用 **body 裡的 `uid`** 去查的：

```ts
const { uid, email } = body;
const userSnap = await adb.collection('users').doc(uid).get();   // ← uid 是呼叫端寫的
```

只要知道任何管理員帳號的 uid，送 `{action:'trigger', uid:'<管理員uid>', email:'x'}` 就通過。
把 email 拿掉只是關掉其中一半。

**修法**：新增 `src/lib/require-admin.ts`，驗證 `Authorization: Bearer <Firebase ID token>`，
uid 一律取自 `verifyIdToken()` 的結果（`checkRevoked: true`，帳號停用即時失效）。
前端 `AdminPanel` 改帶 token，不再送 uid/email。

### 2. 🔴 `DELETE /api/ai-analysis` 完全沒有授權

```ts
export async function DELETE() {          // 沒有任何檢查
  queue.splice(0, queue.length);
}
```

任何人 `curl -X DELETE https://<host>/api/ai-analysis` 就能清空訊息佇列。
**修法**：套用 `requireAdmin()`。

### 3. 🔴 推送路徑零授權 → 對全體使用者的內容注入

`POST /api/ai-analysis`（非 trigger 分支）沒有任何授權，只有 10 秒一次的節流。
而 `GET` 是**公開**的 —— `AiNewsTicker` 每 15 秒替所有使用者拉一次跑馬燈。
兩者相加：任何人 POST 一段文字，就會出現在**每一個使用者**的跑馬燈上。

**修法**：推送路徑改用 `x-cron-secret`（server-to-server；沒有任何瀏覽器端呼叫這條路徑）。
GET 維持公開 —— 它本來就該給所有人看，鎖了會讓跑馬燈全空。

> ⚠ 稽核過程中一度把 GET 也鎖成 admin-only，那會弄壞所有使用者的跑馬燈。
> 已在程式碼註解標明，不要再改。**要收的是「誰能寫入」，不是「誰能讀」。**

### 4. 🟠 秘密比較不是 timing-safe

3 處 `req.headers.get('x-cron-secret') === secret`。字串比較在第一個不同的位元組就回傳，
回應時間隨「猜對幾個字元」變化，可被逐字元量出來。

**修法**：新增 `src/lib/cron-auth.ts`，`secretEquals()` 先 SHA-256 再 `timingSafeEqual`
（先 hash 是為了讓兩邊長度一律 32 bytes —— `timingSafeEqual` 長度不同會 throw，那本身就洩漏長度）。
套用於 `cron/daily-close`、`ai/stock-note`、`cron/backtest`。

## 後續補齊（2026-08-01）

### Rate limiting ✅
`src/lib/rate-limit.ts`：per-IP 滑動窗，套在 11 個端點 ——
扇出上游的 9 支（yahoo-quote/candles×2/history×2/all-time-high/indicators/
rating/stock-intraday，30~120/min）＋ ai-analysis POST/DELETE（10/min）。
只限「扇出上游」與「昂貴操作」；一般 GET 由 CDN s-maxage 擋，不疊限流。

**誠實界定**：無 Redis 時是 in-memory，maxInstances=5 之下有效上限≈設定值×5
（實測 40 連發：38×200＋2×429，正是 per-instance 語意）——仍是真實的濫用天花板。
設 `UPSTASH_REDIS_REST_URL`/`TOKEN` 即自動切換為全域一致（帳號需自行申請，免費層即可）。
429 回 Retry-After + IETF RateLimit-* 標頭；限制器故障 fail-open。

### CSP ＋ 安全標頭 ✅
`firebase.json` `source:"**"`：CSP／nosniff／X-Frame-Options DENY／
Referrer-Policy／Permissions-Policy／HSTS。CSP 白名單依實際盤點：
Google 登入（apis.google.com + frame-src authDomain/accounts.google.com）、
Google Fonts、Firebase(*.googleapis.com)。
`script-src 'unsafe-inline'` 是**已知取捨**：Next.js hydration/RSC payload 是
inline script，無 nonce 基礎設施拿不掉；外部 script 注入仍被擋，
且全站零 dangerouslySetInnerHTML（已稽核）。
瀏覽器實測：頁面渲染、字型、API、登入視窗全部正常、零 CSP violation。
⚠ Google 登入的完整 popup 流程未實測（需真帳號）——首次登入時留意。
