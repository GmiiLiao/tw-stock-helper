# LLM 停損約定：提示詞、輸出格式、驗證規則（stop-v1.1 定稿）

> 這是 SKILL.md §3.5、§10 的全文。只要是會讓 LLM 讀到、寫出停損的程式，都要照本檔做。
> 適用的程式有：持股分析、個股波段分析、問AI，以及將來任何新的提示詞。**非投資建議。**
> **時程**：S3（影子期）**不改任何提示詞**，只用 `measure` 模式量測現有輸出（§4）。§1.1、§1.2 的提示詞改動從 S5 起上線。
> **v1.1 變更**：使用者第 4 項裁定「LLM 只能照抄系統停損」。①提示詞改給生效停損與它的**來源標籤**（成本線、ATR 帶、保本線、追蹤線、事件收緊），**不再另給 ATR 帶的當日值**（v1 的「結構參考價」）；②T5 改為 `bandAsStop`；③「AI 提議停損」選擇題（§1.3、§3）會占 Ollama，**列為第二階段，本次不實作**。

## 0. 原則

1. **停損數字由程式決定。** LLM 只能原樣引用（`STOP_REF`）。它**永遠不填數字**。第二階段的選擇題也只選代號，不填數字。
2. **LLM 的輸出一律先驗證，再存檔或顯示。** 驗證失敗就套用規則值並記錄原因，不能靜默丟掉。
3. **處置／注意是交易限制，不是走勢強弱。** 提示詞要給 `riskNoteText`，而且不得給含扣分的 score；強弱一律用 `techScoreText`（`baseScore`／`baseSignal`）。
4. **新聞不由 LLM 改停損。** 規則類重大利空由程式依類別權重收緊停損（SKILL §10A），LLM 只引用收緊後的生效停損。提示詞不給新聞影響權重 `w`（研究期只顯示，SKILL §10B），也不給類別權重。
5. **不另給會被誤認成停損的數字。** ATR 帶當日值、買點、目標價都可能被 LLM 寫成停損；v1.1 只給生效停損一個數字（標準買點與目標價照原功能保留，但規則句明說它們不是停損）。

## 1. 提示詞片段（S5 起）

### 1.1 持股分析（`buildPrompt`，HEAD `ai-daemon.mjs:726-756`；工作樹 `:727-757`）

**現行**（HEAD `:734`）：

```
目標價(AI推估)：…；停損 ${st.stopLoss}
```

`st.stopLoss` 是 `/api/rating` 的 ATR 帶（`stockHistory`／Yahoo 日 K、以前一完整交易日官方收盤夾值），不是生效停損。

**改為**：

```
目標價(AI推估)：…
停損（系統規範 stop-v1.1·{sourceLabel}·只升不降）：{stop}
```

`sourceLabel` 依綁定來源而定（`stopSourceLabel(src, { form: 'prompt' })`；整行由 `stopPromptLines(res, { event, exAdjusted })` 產生）：

| 來源 `stopSource` | sourceLabel |
|---|---|
| `cost` | `成本線·還原成本 {adjCost} −8%` |
| `atrBand` | `ATR 帶·{MM/DD} 收盤設定` |
| `breakeven` | `保本線·持有期最高收盤曾達 +{x}%` |
| `trail` | `追蹤線·持有期最高收盤 {holdHigh} −3 ATR` |
| `event` | `事件收緊·{MM/DD} {類別名}，至 {MM/DD}`（類別名例：法律事件、財務危機、工安停工、裁罰訴訟） |
| 核可的 AI 提議（第二階段） | `AI 停損·{依據}` |
| 自訂（第二階段） | `自訂` |

做過除權息或減資調整的部位，再加一行：`（已依除權息／減資調整）`。

**規則句**加在 `STRICT_RULE` 之後：

```
【停損規則】停損數字只能原樣引用上面的「停損」，不得自訂、調寬或調緊；不得把支撐買點、ATR 帶當日值或目標價稱為停損；處置／注意是交易限制，不是走勢強弱，不得作為停損理由；新聞不得作為自行調整停損的理由（系統已依規則處理）。
```

**輸出格式**：HEAD `:746`（工作樹 `:747`）的 `TRIGGER` 行不動，原有格式後加一行：

```
STOP_REF: <照抄上面的停損數字>
```

**解析順序**（必要）：`parseStopRef(text)` → `stripStopRef(text)` → 才跑 `parseRationale`／`parseSwing`／`parseTrigger`。
`parseRationale`（`/分析…([\s\S]+?)(?:\n波段建議|$)/`）與 `parseSwing`（`/波段建議…([\s\S]+)/`）都擷取到全文結尾（HEAD `:754-760`）。不先剝除，`STOP_REF` 會落在正文尾端原樣顯示給使用者。

### 1.2 個股波段分析（`swingForCode`，HEAD `:943-966`；停損字樣在 `:959`、`:966`）與問AI（`buildQAContext`，HEAD `:4283-4293`）

這兩支分析的是**個股**，不是某人的部位，所以沒有成本。

- 把 `、停損 ${st.stopLoss}` 拿掉，改成（有標準買點 B 時）：

  ```
  若以標準買點 B 進場，系統停損＝Y（成本 −8% 與 ATR 帶取高）
  ```

  - `Y = hypotheticalStopLine(B, band)`：`max(ceilTick(B×0.92), band)`，其中 `band` 是 `atrBandOf(該代號官方還原日 K)`，只有在 `band < B` 時才計入；算不出來就只用 `ceilTick(B×0.92)`。
  - B 取 `st.buyZones` 裡標為「標準買點」的價格。沒有 B 時，寫「停損：未持有，依進場價 −8% 與 ATR 帶取高計」，不給數字。
- **問AI 例外**：提問者自己持有該檔時，改給他的生效停損與來源（同 1.1）。這是他本人的資料，可以給；不得給其他使用者的資料。
- 把 `:966` 的「具體波段進出價位與停損」改成「具體波段進出價位；停損只能引用上面的系統停損」。
- 結尾加一行 `STOP_REF: <Y 或生效停損>`。解析順序同 1.1。

### 1.3 AI 提議停損（選擇題）——**第二階段，本次不實作**

> 使用者第 4 項裁定：AI 提議只做影子紀錄；它每個錨定事件要呼叫一次 Ollama，列為第二階段。以下規則保留，等第二階段開工時再依當時的生效停損（v1.1 已含 ATR 帶）重新檢查一次 B1–B6 是否仍合理。

- **錨定事件**：新部位（錨定日＝最早買進日）、加碼（錨定日＝該次加碼日，第 6 項裁定）。執行時點是錨定日之後的資料到齊班車（16:45 起）。
- **候選**：S1＝維持目前生效停損（預設，不受距離界線約束）；S2～S4＝近 10 日低 −0.5ATR、錨定收盤 −3ATR、近 20 日低 −0.5ATR，以 §7 係數表還原、向下取檔。
- **硬界線 B1–B6**：B1 不寬於成本線；B2 距錨定收盤 ≥ max(2×ATR14, 5%)（第二階段參數 `AI_MIN_ATR=2`、`AI_MIN_PCT=5`）；B3 低於最新成交價；B4 不低於目前生效停損；B5 錨點日期與還原價可驗證；B6 只在錨定事件時產生。
- **注意**：v1.1 的生效停損多半是棘輪後的 ATR 帶（SKILL §3A.2），B4 會讓 S2～S4 更難合格；第二階段開工前要重算合格率（v1 在純成本線下為 28.5%）。
- **提示詞模板、輸出兩行（`STOP_CHOICE`、`STOP_REASON`）、驗證 V1–V10、範例**：照 v1 原文（§2 的 `STOP_CHOICE` 列、§3、§5.4、§5.5），不在 v1.1 範圍。

## 2. 輸出解析

| 欄位 | 正規表示式 | 處理 |
|---|---|---|
| `STOP_REF` | `/^\s*STOP_REF\s*[:：]\s*([\d,]+(?:\.\d+)?)\s*$/m` | 去掉逗號後轉成數字；`stripStopRef` 移除整行（含全形冒號、出現在中間的情況） |
| 自由文字中的停損價 | `extractStopPrices`（下列規則） | 擷取後逐筆比對（§4）。`STOP_REF` 結構化欄位才是主要依據 |
| `STOP_CHOICE`、`STOP_REASON` | 第二階段 | — |

**`extractStopPrices` 的規則**（SKILL §10.3 與本檔一致，只有這一套）：

1. 先以 `。；\n` 切句。
2. **停損語境**：句中有「停損／止損／停損價／停損點／停損位」。「跌破」只有在**同一句**另有「停損」或「止損」時才算。
2a. **子句**（2026-10-07 線上查核後加）：停損語境的句子再以「，」（及後面不接數字的半形逗號；後接數字的是千分位）切子句，只看「子句內有停損／止損」或「子句內有跌破」的子句。
    同一子句裡，數字前最近的標籤字是「目標／目標價／目標區間／評分／分數」的不算（不含「買點／進場」，T4 要靠它們）。
    起因：S3 量測把「目標價為 6546.17、6730.1、7006，停損設於 6086.35」裡的目標價、「AI技術評分為66.38」當成停損價，
    daemon 日誌 10/06（台北）1,431 筆停損文字違規中，至少 691 筆是出現在含「目標」句子裡的數字不一致或高於現價（日誌只留句首約 40 字，所以是下限）。
    回傳的 `sentence` 仍是整句，`enforce` 的整句移除口徑不變。
    改口徑後量測基準要重算（10/07 以前的 `stopSpecAudit.llm` 計數含誤報）。
3. 在停損語境的子句裡，取數字 `\d+(?:[.,]\d+)?`，但**排除**：
   - 數字後面緊接 `日`、`週`、`月`、`季`、`年`、`%`、`％`、`MA`、`均線`、`線`、`根`、`檔`、`張`、`倍` 的；
   - 數字前面緊接 `−`、`-`、`－` 而且後面接 `%` 或 `％` 的（例如「停損 −8%」）；
   - 不在參考價（現價；沒有現價時用錨定價）的 0.5～1.5 倍之間的。
4. 模型會原樣回傳 `<…>` 範例角括號，解析前先用 `stripBrackets`（`ai-daemon.mjs:718`）去掉。

這是正規表示式擷取，仍可能誤抓或漏抓（量化 §9-11），所以要有量測期與人工標注（§4）。

## 4. 文字一致性驗證 T1–T5（`validateLlmStopText`）

套用於：持股分析的 `TRIGGER`、`分析`、`波段建議`，個股波段分析 `stockAI.swing`，問AI 的回答。

| # | 規則 | `measure` | `enforce` | 記錄 |
|---|---|---|---|---|
| T1 | `STOP_REF` 存在，而且和停損差 <0.5 檔（等於停損） | 記錄 | 記錄（不改畫面，由 T2 負責改正） | `refMismatch`／`refMissing` |
| T2 | `extractStopPrices` 抓到的每個價格和停損差 ≤1 檔 | 記錄 | 把該數字換成停損；並在**欄位末尾另起一行**加註「（停損以系統規範 stop-v1.1 為準：{stop}）」，同一欄位只加一次 | `textMismatch` |
| T3 | 停損語境中的價格 ≥ 最新成交價 | 記錄 | 整句移除 | `stopAbovePrice` |
| T4 | 同一句同時寫「買點／進場」與「停損」，而且停損數字等於某個買點價格 | 記錄 | 整句移除 | `buyAsStop`（0050 實例：量化 §3.12） |
| T5 | 停損語境的數字等於 **ATR 帶當日值**（±1 檔；含 `/api/rating` 的 `stopLoss`），但不等於生效停損 | 記錄 | 交給 T2 改正 | `bandAsStop`（v1 為 `structAsStop`） |

- 加註**不插進** LLM 的句子，所以系統文字不會出現在含指令詞的句子裡。
- 改寫後的數字本來就在提示詞裡，所以 `checkNumbers` 不會把它當成查不到的數字。
- **S3 量測的比對對象**：推播口徑停損（使用者現在看到的）與 v1.1 影子停損兩個值都比；T5 在 S3 就有意義，因為現行提示詞給的正是 ATR 帶。

### 上線三段

1. **S3 量測（提示詞不變）**：對現有輸出跑 `measure`，只寫日誌與 `stopSpecAudit` 計數。基線：stockAI 58 檔中，53% 的停損和系統差 >1%，51% 落在雜訊區（量化 §3.12）。
2. **S5 提示詞切換**：改成 §1，仍是 `measure`。T1 從這時起才有資料。
3. **`enforce`**：同時滿足才開，而且要經使用者核可：
   - 量測期累積 ≥200 句停損語境擷取；
   - 隨機抽 ≥100 句，由使用者或管理員標注「是否真的是停損價」，標注結果寫進 `stopSpecAudit`；
   - 誤判率的 95% 信賴上界 ≤3%。
   - 前例：`number-check.mjs` 是量測約 5 週、400 次輸出後，由**使用者 2026-10-04 裁定**改為標示，不是自動門檻。

## 5. 範例

### 5.1 通過

輸入：停損 52.35（成本線），ATR 帶當日 49.80（低於成本線，所以不是生效停損），現價 55.00。

```
ACTION: 續抱
TRIGGER: 跌破 52.35 停損；站上 61 加碼
分析: …
STOP_REF: 52.35
```

- T1 符合。
- T2：52.35 與停損一致。「61」所在的子句沒有停損語境；以 `；` 切句後不檢查。

### 5.2 改正（`enforce` 時）

```
TRIGGER: 跌破 49.8 即停損出場
STOP_REF: 52.35
```

- T2：49.8 與 52.35 差超過 1 檔 → 數字改成 52.35；欄位末尾另起一行：

  ```
  TRIGGER: 跌破 52.35 即停損出場
  （停損以系統規範 stop-v1.1 為準：52.35）
  ```

- T5：49.8 等於 ATR 帶當日值 → 記錄 `bandAsStop`。這正是 v1.1 不再把 ATR 帶當日值放進提示詞的原因。
- 「出場」是 LLM 分析既有的語氣，只改數字，不改語氣（SKILL §9 的 LLM 欄位豁免）。

### 5.3 不擷取（誤抓防護；`measure` 與 `enforce` 都不算違規）

| 句子 | 為什麼不算 |
|---|---|
| `若跌破 20 日均線則減碼` | 「跌破」所在的句子沒有「停損」；而且 20 後接「日」 |
| `TRIGGER: 跌破季線(60MA)出脫` | 沒有「停損」；60 後接「MA」 |
| `停損設在近 10 日低點下方` | 10 後接「日」 |
| `停損 −8%` | 數字前是「−」、後是「%」 |
| `跌破月線 48.5 減碼` | 「跌破」所在的句子沒有「停損」（這是減碼條件，不是停損） |
| `停損 5`（現價 55） | 不在參考價的 0.5～1.5 倍之間 |

### 5.4 事件收緊後的引用

輸入：`停損（系統規範 stop-v1.1·事件收緊·10/05 法律事件，至 10/12·只升不降）：98.0`，基礎停損 92.5。

```
TRIGGER: 跌破 98 停損
STOP_REF: 98.0
```

- T1、T2 符合。若 LLM 寫「停損 92.5」→ T2 記 `textMismatch`（92.5 是基礎停損，不是生效停損）。
- LLM 若寫「因法律事件建議把停損提高到 100」→ T2 記 `textMismatch`；語氣屬 LLM 欄位豁免，數字依 `enforce` 改正。
