# LLM 停損約定：提示詞、輸出格式、驗證規則

> 這是 SKILL.md §3.5、§10 的全文。只要是會讓 LLM 讀到、寫出或挑選停損的程式，都要照本檔做。
> 適用的程式有：持股分析、個股波段分析、問AI、AI 提議停損（影子期），以及將來任何新的提示詞。**非投資建議。**
> **時程**：S3（影子期）**不改任何提示詞**，只用 `measure` 模式量測現有輸出（§4）。本檔 §1 的提示詞改動從 S5 起，經使用者核可才上線。

## 0. 原則

1. **停損數字由程式決定。** LLM 只能做兩件事：原樣引用（`STOP_REF`），或在影子期從候選中選一個（`STOP_CHOICE`）。它**永遠不填數字**。
2. **LLM 的輸出一律先驗證，再存檔或顯示。** 驗證失敗就套用規則值並記錄原因，不能靜默丟掉。
3. **處置／注意是交易限制，不是走勢強弱。** 提示詞要給 `riskNoteText`，而且不得給含扣分的 score；強弱一律用 `techScoreText`（`baseScore`／`baseSignal`）。
4. **新聞事件不改停損數字。** v1 不要求、也不解析 LLM 的事件旗標；事件型風險只走新聞識讀管線（`tw-news-impact-analyst`），該管線要讀內文，不能用標題觸發。

## 1. 提示詞片段（S5 起）

### 1.1 持股分析（`buildPrompt`，HEAD `ai-daemon.mjs:726-756`）

**現行**（`:734`）：

```
目標價(AI推估)：…；停損 ${st.stopLoss}
```

`st.stopLoss` 是浮動的結構參考價，不是生效停損。

**改為**：

```
目標價(AI推估)：…
停損（系統規範 stop-v1·{basisLabel}·只升不降）：{stop}
結構參考價（非停損，僅標示支撐位置）：{structRef}
```

`basisLabel` 依停損來源而定：

| 來源 | basisLabel |
|---|---|
| 成本線 | `成本線·還原成本 {adjCost} −8%` |
| 核可的 AI 提議（v1 不存在） | `AI 停損·{依據}` |
| 自訂（第二階段） | `自訂` |

做過事件調整的部位，再加一行：`（已依除權息／減資調整）`。

**規則句**加在 `STRICT_RULE` 之後：

```
【停損規則】停損數字只能原樣引用上面的「停損」，不得自訂、調寬或調緊；不得把支撐買點或結構參考價稱為停損；處置／注意是交易限制，不是走勢強弱，不得作為停損理由。
```

**輸出格式**在原有格式後加一行：

```
STOP_REF: <照抄上面的停損數字>
```

**解析順序**（必要）：`parseStopRef(text)` → `stripStopRef(text)` → 才跑 `parseRationale`／`parseSwing`／`parseTrigger`。
`parseRationale`（`/分析…([\s\S]+?)(?:\n波段建議|$)/`）與 `parseSwing`（`/波段建議…([\s\S]+)/`）都擷取到全文結尾（HEAD `:754-760`）。不先剝除，`STOP_REF` 會落在非處置股的 `rationale` 尾端，或處置股的 `swing` 尾端，原樣顯示給使用者。

### 1.2 個股波段分析（`swingForCode`，HEAD `:943-966`；停損字樣在 `:959`、`:966`）與問AI（`buildQAContext`，HEAD `:4283-4293`）

這兩支分析的是**個股**，不是某人的部位，所以沒有成本。

- 把 `、停損 ${st.stopLoss}` 改成：

  ```
  結構參考價 {structRef}（非停損）
  ```

- 有標準買點 B 時，再加一行：

  ```
  若以標準買點 B 進場，系統停損＝ceilTick(B×0.92)＝Y（成本 −8%）
  ```

  B 取 `st.buyZones` 裡標為「標準買點」的價格。沒有 B 時，寫「停損：未持有，依進場價 −8% 計」，不給數字。
- **問AI 例外**：提問者自己持有該檔時，改給他的生效停損（同 1.1）。這是他本人的資料，可以給；不得給其他使用者的資料。
- 把 `:966` 的「具體波段進出價位與停損」改成「具體波段進出價位；停損只能引用上面的系統停損」。
- 結尾加一行 `STOP_REF: <Y>`。解析順序同 1.1：先 `parseStopRef`、`stripStopRef`，`stockAI.swing` 與問AI 回答只存剝除後的正文。

### 1.3 AI 提議停損（影子期；只在錨定事件時跑）

**錨定事件**：新部位（錨定日＝最早買進日）、加碼（錨定日＝該次加碼日；待使用者裁定，SKILL §13-6）。
**執行時點**：錨定日之後的資料到齊班車（16:45 起），候選用已定版的官方資料計算。

```
你是台股風控助理。下表是程式依「AI 停損規範 stop-v1」算好的停損候選。
你只能從「合格」的候選中選一個代號，或回答 NONE；不得寫出表中沒有的數字。
處置／注意是交易限制，不是走勢強弱，不得作為選擇理由。
嚴格輸出兩行：
STOP_CHOICE: <S1|S2|S3|S4|NONE>
STOP_REASON: <一句話，≤60字，只能引用表中出現的數字，不得含指令詞>

【持倉事實】還原成本 {adjCost}、持有 {heldDays} 個交易日、最新價 {lastTradePx}（{來源：今日成交／{日期} 官方收盤}）、錨定日 {anchorDate} 收盤 {anchorClose}、ATR14 {atr14}（{atrPct}%）
【交易限制】{riskNoteText 或「無」}
【候選】
代號 | 價格 | 依據 | 距還原成本 | ATR 倍數 | 狀態
S1 | {currentStop} | 維持目前生效停損（{basisText}） | … | {k} | 預設（不受距離界線約束）
S2 | … | 近10日低 {low10}（{date}）−0.5×ATR | … | … | 合格／不合格：<原因>
S3 | … | 錨定收盤 − 3×ATR | … | … | …
S4 | … | 20日低 {low20}（{date}）−0.5×ATR | … | … | …
```

- **候選怎麼算**：
  - 用錨定日收盤後已定版的官方 OHLC（chipArchive），以 SKILL §7 的係數表（`mergeFactorItems`：官方除權息＋priceEvents）還原。只用 `applyPriceFactors(…, loadPriceFactors())` 不夠，它沒有一般除權息。
  - 結構候選（S2～S4）向下取到合法檔位，讓停損留在結構的外側。
  - S2～S4 要逐條通過 SKILL.md §3.5 的 B1–B6，才標「合格」。
  - S1 是現狀，固定列出、標「預設」，不受 B2、B3 約束。
  - 不合格的也列出來，附上原因，讓 LLM 理解為什麼不能選。
  - S2～S4 都不合格時（例如 ATR% >4%：max(2ATR,5%) 已大於 8%，結構上不可能合格），表照列，但不呼叫 LLM，直接記 `choice:'S1'`、`status:'noEligible'`。
- **`lastTradePx`**：盤中用今日真成交價（`realTrade`、不是處置股、不在 13:24–13:35）；其他時候用最後交易日的官方收盤。來源寫進表內與紀錄。
- **不給 LLM 的資料**：浮動帶 `st.stopLoss`、0–100 分數、其他使用者的資料。
- **Ollama 成本**：
  - 一個錨定事件只跑一次，不每天跑。
  - 排在低優先序（`askOllama(…, { priority: -1 })`），不得擠掉新聞識讀與持股分析。
  - 要不要跑，待使用者裁定（SKILL §13-4）。
- **v1 不跑「個股波段候選」**：沒有部位就沒有成本線，B1 無從檢查。

## 2. 輸出解析

| 欄位 | 正規表示式 | 處理 |
|---|---|---|
| `STOP_REF` | `/^\s*STOP_REF\s*[:：]\s*([\d,]+(?:\.\d+)?)\s*$/m` | 去掉逗號後轉成數字；`stripStopRef` 移除整行（含全形冒號、出現在中間的情況） |
| `STOP_CHOICE` | `/STOP_CHOICE\s*[:：]\s*(S[1-4]\|NONE)\b/` | 只取第一個 |
| `STOP_REASON` | `/STOP_REASON\s*[:：]\s*(.+)/` | 截到 60 字 |
| 自由文字中的停損價 | `extractStopPrices`（下列規則） | 擷取後逐筆比對（§4）。`STOP_REF` 結構化欄位才是主要依據 |

**`extractStopPrices` 的規則**（SKILL §10.3 與本檔一致，只有這一套）：

1. 先以 `。；\n` 切句。
2. **停損語境**：句中有「停損／止損／停損價／停損點／停損位」。「跌破」只有在**同一句**另有「停損」或「止損」時才算。
3. 在停損語境的句子裡，取數字 `\d+(?:[.,]\d+)?`，但**排除**：
   - 數字後面緊接 `日`、`週`、`月`、`季`、`年`、`%`、`％`、`MA`、`均線`、`線`、`根`、`檔`、`張`、`倍` 的；
   - 數字前面緊接 `−`、`-`、`－` 而且後面接 `%` 或 `％` 的（例如「停損 −8%」）；
   - 不在參考價（現價；沒有現價時用錨定價）的 0.5～1.5 倍之間的。
4. 模型會原樣回傳 `<…>` 範例角括號，解析前先用 `stripBrackets`（`ai-daemon.mjs:718`）去掉。

這是正規表示式擷取，仍可能誤抓或漏抓（量化 §9-11），所以要有量測期與人工標注（§4）。

## 3. AI 提議（選擇題）的驗證 V1–V10

依序檢查。標「拒收」的一旦不通過，就不採用這次選擇，並記錄 `rejected:<代碼>`。（v1 只有影子紀錄，任何結果都不會變成生效停損。）

| # | 規則 | 不通過時 | 代碼 |
|---|---|---|---|
| V1 | 兩行都能解析，而且 `STOP_CHOICE` 是 S1、某個「合格」候選，或 NONE | 拒收 | `format` |
| V2 | `STOP_REASON` 裡的**每個數字**（不論有沒有單位）都要對得上輸入：價格類與候選表、持倉事實中的價格比對，容差 1 檔；其他數字要逐字出現在輸入中。不使用 `unverifiedNumbers`，因為它只抓帶單位的數字（`number-check.mjs:33-35`），抓不到「53.0」這種裸價格 | 丟掉理由，選擇保留 | `reasonNumber` |
| V3 | 程式重算所選候選的 B1–B5，不信任 LLM | 拒收 | `bound:B1`…`B5` |
| V4 | 不低於目前的生效停損（棘輪） | 拒收 | `loosen` |
| V5 | 低於 `lastTradePx`（來源規則見 §1.3） | 拒收 | `aboveTrade` |
| V6 | 理由不得用處置／注意來收緊或放寬：同一句同時出現「處置｜注意」與「收緊｜提高｜放寬｜下修｜調整停損」 | 拒收 | `riskReason` |
| V7 | 理由不得含指令詞：建議、應、請、必須、立即、賣出、出場、加碼、續抱、認賠 | 丟掉理由，選擇保留 | `imperative` |
| V8 | **時效**：候選表的資料日（`dataDate`，產生候選所用的定版資料日）必須等於最近一個已定版收盤日（`latestDate`）。這和 OHLC 的錨定日是兩件事；**沒有套用期限** | 拒收 | `stale` |
| V9 | 檔位：最終價格由程式取到合法檔位，LLM 不碰價格 | — | — |
| V10 | 同一份分析的自由文字若提到停損，要和生效停損一致（§4 的 T2） | 記錄 | `textMismatch` |

- **影子期**：通過驗證的選擇記成 `ai.status='shadow-accepted'`，不會變成生效停損，也不發任何警示。
- **生效**：v1 沒有生效路徑（SKILL §11-5）。v2 若要生效，候選要依錨定事件重新產生，不沿用舊表。
- **拒收率高不代表錯。** 每天記錄拒收率與原因分布。V6、V7 是關鍵詞規則，可能誤判，要用影子紀錄校正。

## 4. 文字一致性驗證 T1–T5（`validateLlmStopText`）

套用於：持股分析的 `TRIGGER`、`分析`、`波段建議`，個股波段分析 `stockAI.swing`，問AI 的回答。

| # | 規則 | `measure` | `enforce` | 記錄 |
|---|---|---|---|---|
| T1 | `STOP_REF` 存在，而且和停損差 <0.5 檔（等於停損） | 記錄 | 記錄（不改畫面，由 T2 負責改正） | `refMismatch`／`refMissing` |
| T2 | `extractStopPrices` 抓到的每個價格和停損差 ≤1 檔 | 記錄 | 把該數字換成停損；並在**欄位末尾另起一行**加註「（停損以系統規範 stop-v1 為準：{stop}）」，同一欄位只加一次 | `textMismatch` |
| T3 | 停損語境中的價格 ≥ 最新成交價 | 記錄 | 整句移除 | `stopAbovePrice` |
| T4 | 同一句同時寫「買點／進場」與「停損」，而且停損數字等於某個買點價格 | 記錄 | 整句移除 | `buyAsStop`（0050 實例：量化 §3.12） |
| T5 | 停損語境的數字等於結構參考價（±1 檔），但不等於停損 | 記錄 | 交給 T2 改正 | `structAsStop` |

- 加註**不插進** LLM 的句子，所以系統文字不會出現在含指令詞的句子裡。
- 改寫後的數字本來就在提示詞裡，所以 `checkNumbers` 不會把它當成查不到的數字。

### 上線三段

1. **S3 量測（提示詞不變）**：對現有輸出跑 `measure`，比對兩個值：推播口徑停損（使用者現在看到的），以及 v1 影子停損。只寫日誌與 `stopSpecAudit` 計數。
   - 現有基線：stockAI 58 檔中，53% 的停損和系統差 >1%，51% 落在雜訊區（量化 §3.12）。
2. **S5 提示詞切換**：改成 §1，仍是 `measure`。T1 從這時起才有資料。
3. **`enforce`**：同時滿足才開，而且要經使用者核可：
   - 量測期累積 ≥200 句停損語境擷取；
   - 隨機抽 ≥100 句，由使用者或管理員標注「是否真的是停損價」，標注結果寫進 `stopSpecAudit`；
   - 誤判率的 95% 信賴上界 ≤3%（例如 100 句全對時，上界約 3%）。
   - 前例：`number-check.mjs` 是量測約 5 週、400 次輸出後，由**使用者 2026-10-04 裁定**改為標示，不是自動門檻。

## 5. 範例

### 5.1 通過

輸入：停損 52.35（成本線），結構參考價 49.80，現價 55.00。

```
ACTION: 續抱
TRIGGER: 跌破 52.35 停損；站上 61 加碼
分析: …
STOP_REF: 52.35
```

- T1 符合。
- T2：52.35 與停損一致。「61」所在的子句沒有停損語境；以 `；` 切句後不檢查。

### 5.2 改正（`enforce` 時）

```
TRIGGER: 跌破 49.8 即停損出場
STOP_REF: 52.35
```

- T2：49.8 與 52.35 差超過 1 檔 → 數字改成 52.35；欄位末尾另起一行：

  ```
  TRIGGER: 跌破 52.35 即停損出場
  （停損以系統規範 stop-v1 為準：52.35）
  ```

- T5：49.8 等於結構參考價 → 記錄 `structAsStop`。
- 「出場」是 LLM 分析既有的語氣，v1 只改數字，不改語氣（SKILL §9 的 LLM 欄位豁免）。

### 5.3 不擷取（誤抓防護；`measure` 與 `enforce` 都不算違規）

| 句子 | 為什麼不算 |
|---|---|
| `若跌破 20 日均線則減碼` | 「跌破」所在的句子沒有「停損」；而且 20 後接「日」 |
| `TRIGGER: 跌破季線(60MA)出脫` | 沒有「停損」；60 後接「MA」 |
| `停損設在近 10 日低點下方` | 10 後接「日」 |
| `停損 −8%` | 數字前是「−」、後是「%」 |
| `跌破月線 48.5 減碼` | 「跌破」所在的句子沒有「停損」（這是減碼條件，不是停損） |
| `停損 5`（現價 55） | 不在參考價的 0.5～1.5 倍之間 |

### 5.4 拒收（選擇題）

```
STOP_CHOICE: S3
STOP_REASON: 因列入處置股，提高停損至 54.6 較安全
```

- V6：同一句出現「處置」與「提高停損」→ 拒收，代碼 `riskReason`。
- 另外，假設 S3 本來就標「不合格：距收盤 <5%」→ 也違反 V1，代碼 `format`。
- 結果：記 `rejected`；生效停損不受影響（v1 本來就不會生效）。

### 5.5 丟掉理由（選擇題）

```
STOP_CHOICE: S2
STOP_REASON: 跌破近10日低 53.0 代表結構轉弱
```

- V2：抓到兩個數字。「10」與輸入中的「近10日低」逐字相符；「53.0」是價格，和表中的近 10 日低 54.20 差超過 1 檔 → 丟掉理由，代碼 `reasonNumber`，選擇保留。
- V3：S2 程式重算後通過。
- 結果：記為 `shadow-accepted`，影子期不生效。

## 6. 紀錄欄位

| 紀錄 | 位置 | 內容 |
|---|---|---|
| `stopLlmViolation` | daemon 日誌，以及 `stopSpecAudit/{date}.llm` 的計數 | 時間、來源（holding／swing／qa／proposal）、代碼、規則碼、原數字、改正值、所在句子 |
| 人工標注 | `stopSpecAudit/{date}.llmLabels` | 抽樣句數、標注者（管理員或使用者）、誤判數、95% 上界 |
| AI 提議 | `stopBooks/{uid}.positions[code].ai` | `candidates`、`choice`、`status`（`none`／`noEligible`／`shadow-accepted`／`rejected`）、`reasons[]`、`dataDate`、`decidedAt` |

公共的 `stopSpecAudit` 只放**計數**，不放個人持股代號。

> 非投資建議。
