# 模式規則（第二階段，等 ND14 才接到持股）

> **v1 不啟用。** `HoldingItem` 沒有模式欄位（`src/lib/store.ts:24-33`），所以 v1 所有持股一律走 `general`（SKILL.md §2）。
> 本檔先把短線、波段兩份提案中屬於特定模式的規則定下來。等使用者核可 ND14（持股的 `plan` 欄位與自訂停損 `userStop`），共用函式再依 `plan` 分派。
> 當沖工作台觀察單與 AI 實驗模擬單，**現在就照各自的既有規則**運作（`scripts/lib/daytrade-setups.mjs`）。本檔只是把規則寫清楚。**非投資建議。**

## 0. 模式判定（第二階段）

1. 明確欄位 `plan`：`general`、`swing5`、`long`、`overnight`、`day`。
2. 當天的 `TradeRecord.dayTrade === true` → `day`。這個欄位是賣出時才寫入，只能用來事後歸類。
3. 其他一律 `general`。

**不得**用「買進日＝前一交易日」推定隔日沖。原因：`checkOpenSell`（`ai-daemon.mjs:15114-15145`）會因此對波段持股在買進隔天也發「開低直接認賠」（短線 §1.6）。

## 1. 當沖（`day`）

| 項目 | 規則 | 依據 |
|---|---|---|
| 停損價 | 結構停損，進場時寫定。三種型態的錨點：<br>· ORB：突破後到再攻之間的最低點，與區間上緣比取低者<br>· 突破回踩：量縮回測的最低點<br>· 開低反轉：前 5 根的較高低點 | `daytrade-setups.mjs` |
| 檔位 | 多單向下取（留在結構外側），ETF 用 ETF 檔位 | 短線 §3.2 |
| 界線 | 停損距離 `d/entry ≤ 3%`（`DESK_PARAMS.maxStopPct`）；停損 > 今日跌停價；`d > 0` | 停損若低於跌停價，今天就觸發不了 |
| 名單層排除 | 處置股、不可當沖的股票 | `ai-daemon.mjs:267` 交易規則 |
| 時間出場 | 13:20（`DESK_PARAMS.closeOut`）。是否提早到 13:15 待使用者裁定 | — |
| 提前出場條件 | VWAP 停損（先站上，再連 2 根失守）；20 根時間停損 | 不改停損價本身 |
| 獲利後 | 達 1R 移到進場價；達 2R 移到 1R；達 3R 出場。只收緊。達標只認成交（1 分 K 高點） | 工作台日誌：保本 −0.16R（n=6）、追蹤 +0.53R（n=3）、3R +3.00R（n=4），**樣本不足** |
| 部位張數 | `floor(單筆上限 ÷ (1.5 × d × 1000 ＋ 每張來回成本))` | 結構停損實際出場平均 −1.30R（n=10），所以用 1.5R。**樣本不足**，累積 ≥30 筆後要校正 |
| 觸及 | 只在快線（5 秒）迴圈判定；用「設定後最低成交」（1 分 K 低點），因為今日最低可能發生在進場之前 | 60 秒的 alertLoop 太慢（H5） |
| 一級警示 | `stopTouch`、`dtCloseout`（13:20 時持股紀錄仍有當日當沖部位）、`dtCarried`（13:30 後仍未沖銷） | 持股紀錄可能漏記或已賣未記，所以文字只寫「持股紀錄仍有」 |
| LLM | 選擇題，候選是錨點 `ORB_LOW`、`VWAP`、`PREV_LOW`、`PULLBACK_LOW`。所選停損與錨點差 0–3 檔，且在外側。處置股、不可當沖的股票提出當沖停損一律拒收 | 短線 §4.3 |
| 影子 | 開發 ≥100 筆、驗證 ≥30 筆後，才提請啟用 | 工作台迭代規則 |

## 2. 隔日沖（`overnight`）

| 項目 | 規則 | 依據 |
|---|---|---|
| 停損 | **沒有價格停損**：`kind='time'`，出場時點＝次一交易日 09:00 開盤 | 鐵律 `ai-daemon.mjs:598`。候選股次日開低時（n=2,611）：開盤出 −1.24%／−0.89%，收盤出 −1.44%／−1.40%，破前日低才出 −1.42%（短線 §11-2）。兩窗同向 |
| 畫面 | 「出場時點：MM/DD 09:00 開盤（隔日沖計畫）」，不顯示距停損 | — |
| 開高 | 也是開盤出，沒有移動停利 | 開高（n=4,533）：開盤出 +1.47%／+0.99%，收盤出 +0.99%／+0.38% |
| 過時仍持有 | 09:05 後持股紀錄仍在 → 轉成 `general`（原成本、原買進日），並揭露「已過隔日沖出場時點 N 分」 | 量化 §4.1 也是同一做法 |
| 尾端揭露 | 候選母體後 40% 的隔夜 P1 為 −5.41%（n=3,265）；漲停收盤母體後 40% 為 −9.05%（n=10,704） | 只用來算部位上限，**不是**停損 |
| 一級警示 | `onOverdue`（09:05 後持股紀錄仍有） | — |
| LLM | 只接受 `STOP_CHOICE: OPEN_EXIT`；任何數字價格一律拒收 | 短線 §4.3-6 |

當沖到 13:30 仍未沖銷，就自動改用隔日沖規則，並發一級 `dtCarried`。

## 3. 波段 5 日（`swing5`，`src/lib/trading-mode.ts:53`）

| 項目 | 規則 |
|---|---|
| 初始停損 | 進場日最低價（還原），再夾在 ≥ 成本線之上 |
| 太近 | **不拒絕**，因為模式規則優先；改為揭露，例如：「停損距離 1.4%（0.5 ATR）：本站回測，距離 ≤1 ATR 時 5 日內觸及率約 5～7 成」 |
| 時間 | 第 5 個交易日收盤是模式出場點，發二級提醒 |
| 獲利後 | 不做保本線，5 日內通常到不了 |

依據：這是使用者既有的模式規則（`src/lib/trading-mode.ts:53` 原文「破前低無條件停損」；本表寫成「進場日最低價」是提案的解讀，ND14 時一併確認），**不是**回測支持的停損。既有實驗的結論正好相反：SWING_SKILL（HEAD `ai-daemon.mjs:396`）記載 12 組出場規則在主窗每一格的平均都是負的、樣本外每一格都比單純抱到第 5 日差，「破今低停損在 5 日尺度太緊——觸發率 47～62%」。要不要沿用這條模式規則，交使用者在 ND14 裁定時決定。

## 4. 存股（`long`）

- 不發一級價格停損警示。
- 只顯示事實：距成本 −8% 線、季線、論點支持度。

## 5. 使用者自訂停損（`userStop`，ND14）

- 優先序最高。只要是合法檔位就採用。
- 寬於成本線時照樣採用，並標「自訂停損寬於系統上限 −8%」。
- 系統的棘輪不會把它往下移。使用者自己改寬要留紀錄，並標「使用者改寬」。
- 換版原因 `userSet`，是 SKILL §3.4「只升不降」的例外之一；改寬後再觸及算新事件。
- 自訂停損 ≥ 還原成本時，歸「成本上方停損」（`line:'aboveCost'`），可發幾級由 ND14 時裁定。

## 6. 需要的新欄位（第二階段；名稱要先在 `scripts/check-field-conventions.mjs` 登記）

| 欄位 | 位置 | 說明 |
|---|---|---|
| `plan` | `HoldingItem` | `'general' \| 'swing5' \| 'long' \| 'overnight' \| 'day'` |
| `userStop` | `HoldingItem` | 數字或 null |
| 「設定後最低成交」 | daemon 記憶體，並持久化到 `stopBooks/{uid}` | 當沖與今日才設的停損需要 |
| 快照帶昨收 `prev`、MIS 跌停價 `w` | daemon 快照（主迴圈與快線合併都要帶） | 除權息「`y` 與歸檔前收比對」安全網、跌停事實句改用官方跌停價（SKILL §4.4、§7） |
| 單筆／單日風險上限 | 目前只在前端 localStorage（`dtDeskRisk`） | 要給 daemon 算張數，就得搬進 Firestore |
